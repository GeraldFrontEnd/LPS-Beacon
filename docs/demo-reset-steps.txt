LPS-Beacon: reset the data bucket and load the demo data (copy-paste, Ubuntu / WSL)
====================================================================================
Do the code deploy FIRST (docs/deploy-steps.txt steps 0-4), then this.
The data bucket is lps-beacon-data. The website bucket (lps-beacon-frontend) is NOT touched here.


0. SIGN IN
----------
aws sso login --profile lps
export AWS_PROFILE=lps
export AWS_PAGER=""
BUCKET=lps-beacon-data


1. LOOK BEFORE DELETING
-----------------------
aws s3 ls s3://$BUCKET/
aws s3 ls s3://$BUCKET/ --recursive --summarize | tail -3
aws s3api get-bucket-versioning --bucket $BUCKET
# If versioning says "Enabled", deleted files stay as old versions (recoverable, and they still cost storage).


2. OPTIONAL BACKUP TO YOUR LAPTOP (recommended: the uploads were real sample files)
-----------------------------------------------------------------------------------
mkdir -p ~/lps-beacon-backup-$(date +%Y%m%d)
aws s3 sync s3://$BUCKET ~/lps-beacon-backup-$(date +%Y%m%d)


3. DELETE EVERYTHING IN THE DATA BUCKET
---------------------------------------
# Dry run first: lists what would go, deletes nothing.
aws s3 rm s3://$BUCKET --recursive --dryrun | tail -5
# The real delete:
aws s3 rm s3://$BUCKET --recursive
# Check it is empty (prints nothing, or "Total Objects: 0"):
aws s3 ls s3://$BUCKET/ --recursive --summarize | tail -2

# This also removes the capacity plan edits (plan/edits.json), the management target (plan/management_target.json),
# review runs and the chat's results files. Chat history and the activity bell live in DynamoDB, not S3: old upload
# entries will still show under the bell. That is harmless; ask Claude for a DynamoDB clean-up if it matters.
